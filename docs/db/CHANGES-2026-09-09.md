## What landed

- `public.election_cycles`: one row per election the PAC takes applications
  for, with the enforced window (`applications_open_at` /
  `applications_close_at`), the Ohio board of elections dates beside it, a
  three-state `is_open_override`, and `is_published`.
- `public.cycle_is_open(election_cycles)`: the only definition of open.
  `public.cycle_accepts_applications(uuid)` wraps it as SECURITY DEFINER for
  the insert gate.
- On `endorsement_applications`: `cycle_id` (now `not null`), `submitted_at`
  (backfilled from `created_at`), `was_late`.
- Views `public_election_cycles` (published only, no `override_note`) and
  `admin_election_cycles` (everything, plus counts). Both security_invoker.
- The anon INSERT policy was **rewritten**, not supplemented, to require a
  published, open cycle and `was_late = false`.

## The insert policy is a rewrite, and that is the point

The work order specified a new policy named `public_insert_open_cycles_only`
beside the existing `anon can submit applications`. Permissive policies are
OR'd, so that would have left the original ungated policy as a second door and
the gate would have done nothing. The existing policy now carries the cycle
check.

The gate calls the SECURITY DEFINER wrapper rather than sub-selecting
`election_cycles` inline. An inline sub-select runs under the caller's own RLS,
which would have made every public submission depend on anon keeping SELECT on
the cycles table. Tighten that read policy some day and applications start
failing for a reason nobody would think to look for.

## Backfill differs from the work order, deliberately

The work order said to put every existing application on `2026-general`. Two of
the 24 are 2027 races and one of them is the Columbus mayoral application,
whose December 4 deadline is the one committed in writing to both campaigns. A
blanket backfill would have filed it under a cycle that closes September 30.

Rows were matched to the election they are actually for:

| Cycle | Applications |
|---|---|
| 2026-general | 22 |
| 2027-columbus-municipal | 1 (Mayor, Franklin County) |
| 2027-general | 1 (Council At-Large, Cuyahoga County) |
| 2027-primary | 0 |

Anything unrecognized still falls back to `2026-general`.

## Worth knowing

**anon has INSERT but not SELECT on `endorsement_applications`.** A client that
adds `.select()` to the insert, or sends `Prefer: return=representation`, gets
`42501 permission denied for table` before RLS is even consulted. The form
sends `return=minimal` and must keep doing so. This cost a confusing test cycle
and would cost a confusing outage.

**Two application windows are policy, not statute**, and are flagged CONFIRM in
the seed file: 2026-general closing 2026-09-30, and 2027-primary closing
2027-02-19. Both are editable from `/admin/endorsements/cycles` without a
deploy.
