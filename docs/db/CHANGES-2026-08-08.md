## Security: anon could read whole endorsement applications

`endorsement_applications` carried `anon can read endorsed candidates`, a
policy allowing `SELECT *` on any row with `status='endorsed'`. The anon key is
published in the site's client code, so anyone could read, for every endorsed
candidate: campaign `email` and `phone`, the typed `signature`,
`conflicts_disclosure`, internal `reviewer_notes`, `reviewed_by`, and
`user_agent`. The policy also ignored `is_published`, so an endorsement recorded
before its announcement was readable the moment the status flipped — Cara Jacob
was in that state when this was found.

Fixed: policy dropped, `SELECT` revoked from `anon`. The public surface is the
`public_endorsements` view, which is owner-privileged (`postgres` has
`BYPASSRLS`) and therefore keeps working with no anon policy on the base table.
Verified after applying: `set role anon` is denied on the table and still
returns the four published endorsements from the view.

## `endorsed_at` is a real column

`public_endorsements.endorsed_at` was `updated_at`, so any edit to a row —
fixing a typo in a bio, toggling publication — silently moved the endorsement
date the public page displays.

- Added `endorsement_applications.endorsed_at timestamptz`, backfilled from
  `coalesce(reviewed_at, updated_at)` for the five endorsed rows.
- Trigger `trg_endorsement_stamp_endorsed_at` (`before update of status`)
  stamps it when a row becomes endorsed and clears it when a row leaves that
  status, so a re-endorsement dates fresh instead of republishing the old date.
- View rebuilt: `endorsed_at` reads the column; `endorsement_path` appended so
  the public page can filter by the office level a candidate actually applied
  under instead of pattern-matching the office title.

## The process has no interview step

Ohio Pride does not interview candidates. `endorsement_path_meta.interview_note`
promised every applicant "a virtual interview of one hour or less before any
board vote", and the judicial `intro_body` ended "the interview is where we go
deep".

- Column renamed `interview_note` → `process_note` and rewritten for all four
  paths: review against the public record, Board vote, notification either way.
- Judicial `intro_body` rewritten without the interview sentence.

The matching copy changes are in `public/endorsement/screening/index.html`, the
confirmation page, and `/endorsements`. **The column rename is live now**, so
the deployed application form renders an empty note (it reads `interview_note ||
''`) until the code ships.

## `endorsement_path` backfilled

Seven applications predate the path-aware form and had a null
`endorsement_path`, so the admin and the PDF packet could not tell which
questionnaire the candidate answered. Backfilled from the office title where
unambiguous: six to `statewide` (Ohio House / State Senate / Ohio State
Treasurer), one to `local` (Council At-Large). No rows left null.

## Two dead columns dropped

- `submission_ip` — zero rows, and impossible to populate: the application form
  inserts from the browser.
- `generated_pdf_path` — zero rows; packets are rendered on demand by
  `/api/endorsement-pdf`.

The anon INSERT policy named `generated_pdf_path`, so it was rebuilt without it
and with `endorsed_at is null` added to the check.

## Deliberately not done

The legacy `q1..q10` answer columns were **not** dropped. Ten real applications
still answer through them, their `legacy_q*` mirror in `responses` is values
only (the `q*_explanation` text exists only in the columns), and the original
prompts are no longer recoverable from git. Dropping them would degrade the
deliberation record. `lib/endorsement-answers.mjs` is now the single reader for
both the admin page and the PDF packet and handles all three answer eras.
